# AGENTS.md

Instructions for AI coding agents working in this repository. Human contributors: see
[`CONTRIBUTING.md`](CONTRIBUTING.md), which this file summarises.

## Checks

Every change must leave these passing:

```bash
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run mypy canon
uv run canon validate cases/
uv run python scripts/check_claims.py
```

## Hard rules

- **Do not edit `cases/` or `rejected/cases/`.** The bank is frozen; a change to a case changes its
  hash and invalidates every published result on it. Report suspected errors instead.
- **Keep the design invariants** in [`CONTRIBUTING.md`](CONTRIBUTING.md#design-invariants). In
  particular: no model client imported by the core modules, no LLM judge in primary scoring,
  paired frames rendered from one template, refusals never coded as a middle answer, letters
  never averaged.
- **Apply the drift test** before any change that could alter what is measured. If the answer is
  not a plain yes, stop and report.
- **Never invent facts, sources, dates or legal options,** and never set `verified_by` or
  `verified_at`.
- **Do not start paid model runs** without explicit approval. Use `--model mockllm/model` for
  smoke tests, and `canon eval` rather than `inspect eval`.
- **Never print, log or commit** `.env` or any API key.
- If a change alters a number reported in the paper or on the interactive page, update
  `scripts/check_claims.py` in the same change.

## Where things live

- Harness: `canon/`; Inspect integration: `canon/inspect_adapter/`.
- Case authoring: [`docs/CASE_AUTHORING.md`](docs/CASE_AUTHORING.md).
- Aggregates behind the paper: `results/`; generators: `scripts/`.
- Interactive page: `site/index.html`; its `data.js` and figures are generated by
  `scripts/make_blog_data.py` and `scripts/make_blog_figures.py`.
